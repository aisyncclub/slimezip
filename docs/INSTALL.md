## 1. 내려받아 설치하기

### 1단계 — 파일 받기

[**릴리스 페이지**](https://github.com/aisyncclub/zipbar/releases/latest)로 가서 `SlimeZIP-*.zip`을 내려받습니다.

### 2단계 — 압축 풀기

받은 파일을 두 번 누르면 `SlimeZIP.app`이 나옵니다.

### 3단계 — 응용 프로그램으로 옮기기

`SlimeZIP.app`을 **응용 프로그램** 폴더로 끌어다 놓습니다.

> Finder 사이드바에 "응용 프로그램"이 없으면 `⇧⌘A`로 열 수 있습니다.

### 4단계 — 처음 열기

두 번 눌러 봅니다. **여기서 macOS가 한 번 막습니다.**

> **"SlimeZIP이(가) 손상되었기 때문에 열 수 없습니다"**
> 또는 **"확인되지 않은 개발자가 배포했기 때문에 열 수 없습니다"**

**앱이 실제로 손상된 게 아닙니다.** macOS는 인터넷에서 받은 모든 파일에 표시를 붙이고,
애플의 공증(notarization)을 받지 않은 앱이 그 표시를 달고 있으면 실행을 막습니다.
공증에는 연 $99짜리 애플 개발자 계정이 필요한데, SlimeZIP은 아직 받지 않았습니다.

### 5단계 — 한 번만 허용하기

<table>
<tr><td width="40"><b>1</b></td><td> <b>시스템 설정</b>을 엽니다 (<code>⌘Space</code> → "시스템 설정")</td></tr>
<tr><td><b>2</b></td><td>왼쪽에서 <b>개인정보 보호 및 보안</b>을 고릅니다</td></tr>
<tr><td><b>3</b></td><td>오른쪽을 <b>맨 아래까지</b> 내립니다 — <b>보안</b> 항목이 있습니다</td></tr>
<tr><td><b>4</b></td><td>"SlimeZIP이(가) 차단되었습니다" 옆의 <b>확인 없이 열기</b>를 누릅니다</td></tr>
<tr><td><b>5</b></td><td><b>열기</b>를 누르고 맥 암호를 입력합니다</td></tr>
</table>

**처음 한 번만 하면 됩니다.** 그다음부터는 그냥 열립니다.

> **⚠️ 우클릭 → 열기는 이제 안 됩니다.**
> macOS 세쿼이아(15)부터 애플이 그 우회로를 없앴습니다. 위의 시스템 설정 경로가 유일합니다.
> 인터넷의 오래된 안내가 우클릭을 말하고 있다면 그건 세쿼이아 이전 이야기입니다.

메뉴바 오른쪽에 **슬라임이 하나** 생기면 성공입니다. 🎉

## 2. 접근성 권한 켜기

**이 권한이 없으면 목록이 비어 보입니다.** 반드시 켜 주세요.

앱을 처음 실행하면 대화상자가 뜹니다. 놓쳤다면 직접 켜면 됩니다.

**시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용 → SlimeZIP 켜기**

### 왜 필요한가요

macOS 26부터 메뉴바 아이콘을 **제어 센터가 대신 그립니다.** 그래서 창 목록만 봐서는
어느 아이콘이 어느 앱 것인지 알 수 없습니다 — 전부 "제어 센터 소유"로 나옵니다.

접근성 권한이 있으면 각 앱이 스스로 게시한 메뉴바 정보를 읽을 수 있습니다.
그래야 "Tailscale", "카카오톡"처럼 **이름으로** 보여 줄 수 있습니다.

| 권한 없이 | 권한 켜고 |
|---|---|
| 숨기기 · 꺼내기 — 동작함 | 숨기기 · 꺼내기 — 동작함 |
| 목록 — **비어 있음** | 목록 — **앱 이름까지 표시** |

SlimeZIP은 이 권한으로 **읽기만** 합니다. 키 입력을 가로채거나 기록하지 않습니다.
[소스](https://github.com/aisyncclub/zipbar/tree/master/Sources/ZipBarKit/Services)에서 확인하실 수 있습니다.

## 3. 처음 써 보기

### 슬라임을 눌러 보세요

메뉴바의 슬라임을 클릭하면 지금 떠 있는 아이콘이 전부 목록으로 나옵니다.
각 줄 옆의 버튼으로 **넣고 뺍니다.**

| 조작 | 결과 |
|---|---|
| **클릭** | 아이콘 목록 열기 |
| **⌥ + 클릭** | 접기 ↔ 펴기 바로 전환 |
| **우클릭** | 설정 · 종료 메뉴 |

### 슬라임이 개수를 알려 줍니다

<img src="img/scale.png" alt="숨긴 개수에 따라 0개부터 5개 이상까지 점점 납작해지는 슬라임">

**개수가 늘어도 아이콘 폭은 22pt 그대로입니다.** 숫자를 붙이면 자리를 더 먹으니,
대신 눌린 정도로 보여 줍니다. 감춰 둔 아이콘에 변화가 생기면 슬라임이 움찔합니다.

### 처음 한 번은 재시작이 필요합니다

어떤 앱의 아이콘을 처음 자리 잡을 때, **그 앱을 한 번 재시작**해야 합니다.
macOS가 아이콘 위치를 앱이 시작할 때만 읽기 때문입니다. SlimeZIP이 대신 종료하고
다시 켜 주니 버튼만 누르시면 됩니다.

**한 번만 하면 됩니다.** 그 뒤로는 클릭 즉시 감췄다 꺼냈다 합니다.

## 4. 문제가 생기면

<details>
<summary><b>슬라임이 안 보여요</b></summary>

<br>

메뉴바가 이미 꽉 차서 SlimeZIP 자기 아이콘이 화면 밖으로 밀렸을 수 있습니다.

1. 다른 앱 몇 개를 종료해 메뉴바에 자리를 만듭니다
2. SlimeZIP을 다시 실행합니다

그래도 안 보이면 저장된 위치가 화면 밖을 가리키고 있을 수 있습니다. 초기화하세요.

```bash
defaults delete com.zipbar.ZipBar
open /Applications/SlimeZIP.app
```

</details>

<details>
<summary><b>"손상되었기 때문에 열 수 없습니다"가 계속 떠요</b></summary>

<br>

[5단계](#5단계--한-번만-허용하기)의 시스템 설정 경로를 아직 안 거치셨을 가능성이 높습니다.
그래도 안 되면 터미널에서 표시를 직접 지울 수 있습니다.

```bash
xattr -dr com.apple.quarantine /Applications/SlimeZIP.app
```

이 명령은 "인터넷에서 받았음" 표시를 지웁니다. 진짜 안전장치이니,
**직접 받은, 믿는 앱에만** 쓰세요.

</details>

<details>
<summary><b>목록이 비어 있어요</b></summary>

<br>

접근성 권한이 꺼져 있습니다. [2번](#2-접근성-권한-켜기)을 봐 주세요.

시스템 설정에서 토글은 켜져 있는데도 비어 있다면, 껐다가 다시 켠 뒤
SlimeZIP을 재시작해 보세요. 앱을 새 버전으로 덮어썼을 때 가끔 이렇게 됩니다.

</details>

<details>
<summary><b>아이콘을 숨겼는데 그대로예요</b></summary>

<br>

그 앱을 아직 재시작하지 않았을 때 그렇습니다. macOS는 아이콘 위치를
앱이 시작하는 순간에만 읽습니다. 패널의 **적용** 버튼을 누르면 SlimeZIP이
해당 앱을 종료했다가 다시 켭니다.

일부 앱은 종료할 때 자기 위치를 다시 저장해서 우리가 쓴 값을 덮어씁니다.
SlimeZIP은 종료가 끝난 뒤 다시 쓰는 방식으로 이걸 피합니다. 그래도 안 되는
앱이 있으면 [이슈로 알려 주세요](https://github.com/aisyncclub/zipbar/issues).

</details>

<details>
<summary><b>맥을 껐다 켜면 설정이 풀려요</b></summary>

<br>

그룹 구성은 저장되지만, **로그인할 때 자동 실행**은 따로 켜야 합니다.
우클릭 → 설정에서 "로그인 시 실행"을 켜 주세요.

</details>

<details>
<summary><b>완전히 지우려면</b></summary>

<br>

```bash
osascript -e 'quit app "SlimeZIP"'
rm -rf /Applications/SlimeZIP.app
defaults delete com.zipbar.ZipBar
```

시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용 목록에서도 빼 주세요.

</details>

## 5. 터미널 한 줄로 설치하기

터미널이 익숙하시면 이 한 줄이면 끝납니다.

```bash
curl -fsSL https://raw.githubusercontent.com/aisyncclub/zipbar/master/scripts/install.sh | bash
```

최신 릴리스를 받아 `/Applications`에 넣고, 다운로드 표시를 지운 뒤 실행합니다.
[1번](#1-내려받아-설치하기)의 5단계를 건너뛰게 해 주는 것뿐, 하는 일은 같습니다.

스크립트가 무엇을 하는지 [직접 읽어 보실 수 있습니다](https://github.com/aisyncclub/zipbar/blob/master/scripts/install.sh).
모르는 스크립트를 `| bash`로 넘기는 건 좋은 습관이 아니니, 읽어 보고 판단하세요.

## 6. 소스에서 빌드하기

직접 고쳐 쓰실 분만 보시면 됩니다. 그냥 쓰시려면 위에서 끝입니다.

### 필요한 것

| | |
|---|---|
| 빌드 도구 | Xcode Command Line Tools |
| Xcode 전체 | 필요 없음 |

```bash
xcode-select --install
```

### 빌드

```bash
git clone https://github.com/aisyncclub/zipbar.git
cd zipbar
./scripts/build-app.sh
open dist/SlimeZIP.app
```

`dist/SlimeZIP.app`이 만들어집니다.

### 서명 인증서 (반복해서 빌드하신다면)

건너뛰어도 앱은 돌아갑니다. 다만 **리빌드할 때마다 접근성 권한이 풀립니다.**

macOS는 권한을 서명의 지문에 묶어 기억합니다. 애드혹 서명은 빌드마다 지문이
바뀌므로, 시스템 설정의 토글은 켜져 있는데 새 빌드는 남남 취급을 받습니다.
고정된 인증서 하나면 이 반복이 사라집니다.

**키체인 접근** → 메뉴 막대의 **키체인 접근 → 인증서 지원 → 인증서 생성**

| 화면 | 입력 |
|---|---|
| 인증서 생성 | 이름 `ZipBar Dev` · 신원 유형 **자체 서명 루트** · 인증서 유형 **코드 서명** · **기본값 무시 체크** |
| 인증서 정보 | 유효 기간 `3650` |
| 키 사용 확장 | **서명** 체크 |
| 확장된 키 사용 | **코드 서명** 체크 |
| 위치 지정 | 키체인 **로그인** |

만들었는지 확인:

```bash
security find-identity -v -p codesigning
```

`ZipBar Dev`가 보이면 `build-app.sh`가 알아서 그 인증서로 서명합니다.

### 진단 도구

OS 업데이트 후 무엇이 깨졌는지 확인합니다. **베타가 나오면 가장 먼저 이걸 돌립니다.**

```bash
./.build/debug/zipbar-probe capabilities   # 각 백엔드가 되는지 요약
./.build/debug/zipbar-probe list           # 열거 결과 전체
./.build/debug/zipbar-probe ax             # 접근성 스윕 상세 (권한 필요)
```
