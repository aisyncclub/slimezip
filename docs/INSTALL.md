# ZipBar 설치 가이드

메뉴바 아이콘을 슬라임이 물어 정리해 주는 macOS 앱입니다.

## 설치 — 한 줄

```bash
curl -fsSL https://raw.githubusercontent.com/aisyncclub/zipbar/master/scripts/install.sh | bash
```

최신 릴리스를 받아 `/Applications`에 넣고, 다운로드 격리 표시를 지운 뒤 실행합니다.
Xcode도 빌드도 필요 없습니다.

**이 스크립트가 격리를 지우는 이유.** ZipBar는 아직 애플 공증(notarization)을 받지
않았습니다. 공증에는 연 $99짜리 Developer ID가 필요합니다. macOS는 내려받은 모든
파일에 `com.apple.quarantine` 표시를 붙이고, 공증되지 않은 앱이 그 표시를 달고
있으면 실행을 막으면서 "손상되었습니다"라고 말합니다 — 실제로 손상된 게 아닙니다.
세쿼이아부터는 우클릭 → 열기라는 예전 우회로도 없어졌습니다.

격리 표시는 진짜 안전장치입니다. 지우는 건 이 프로젝트를 믿기로 한 결정과 같습니다.
그게 내키지 않으면 아래 수동 설치를 쓰세요 — 표시를 지우지 않고, macOS에 예외를
한 번만 허용합니다.

## 설치 — 터미널 없이

1. [릴리스 페이지](https://github.com/aisyncclub/zipbar/releases)에서 `ZipBar-*.zip`을 받습니다.
2. 압축을 풀고 `ZipBar.app`을 **응용 프로그램**으로 옮깁니다.
3. 열면 macOS가 막습니다. **시스템 설정 → 개인정보 보호 및 보안**으로 갑니다.
4. 맨 아래 보안 항목에서 **확인 없이 열기** → **열기** → 암호 입력.

처음 한 번만 하면 됩니다.

## 필요한 것

| | |
|---|---|
| macOS | 14 이상 (26.5에서 개발·검증) |
| 권한 | 손쉬운 사용(접근성) |
| 비용 | 없음 · 오픈소스 |

## 접근성 권한

설치 방법과 상관없이 이 권한은 반드시 필요합니다.

**시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**에서 ZipBar를 켜 주세요.

권한이 없으면 각 앱이 게시한 메뉴바 정보를 읽을 수 없어 목록이 비어 보입니다.
숨기기 자체는 권한 없이도 되지만, 어느 아이콘이 어느 앱 것인지 알 수 없습니다.

# 소스에서 빌드하기

여기서부터는 직접 고쳐 쓰려는 경우입니다. 그냥 쓰려면 위에서 끝입니다.

## 필요한 것 (빌드)

| | |
|---|---|
| 빌드 도구 | Xcode Command Line Tools |

Swift 툴체인이 없으면 먼저 설치하세요.

```bash
xcode-select --install
```

## 1. 내려받아 빌드

```bash
git clone https://github.com/aisyncclub/zipbar.git
cd zipbar
./scripts/build-app.sh
```

`dist/ZipBar.app`이 만들어집니다.

## 2. 서명 인증서 (권장)

소스에서 반복해서 빌드할 때만 해당됩니다. 릴리스를 받아 쓰면 필요 없습니다.

건너뛰어도 앱은 돌아가지만, **리빌드할 때마다 접근성 권한이 풀립니다.**

macOS는 권한을 서명의 지문에 묶어 기억합니다. 애드혹 서명은 빌드할 때마다
지문이 바뀌므로, 시스템 설정의 토글은 켜져 있는데 새 빌드는 남남 취급을
받습니다. 고정된 인증서 하나면 이 반복이 사라집니다.

**키체인 접근** → 메뉴 막대의 **키체인 접근 → 인증서 지원 → 인증서 생성**

| 화면 | 입력 |
|---|---|
| 인증서 생성 | 이름 `ZipBar Dev` · 신원 유형 **자체 서명 루트** · 인증서 유형 **코드 서명** · **기본값 무시 체크** |
| 인증서 정보 | 유효 기간 `3650` |
| 키 사용 확장 | **서명** 체크 |
| 확장된 키 사용 | **코드 서명** 체크 |
| 위치 지정 | 키체인 **로그인** |

"기본값 무시"를 체크하지 않으면 키 사용 화면이 나오지 않아 코드 서명용으로
쓸 수 없습니다. 가장 흔한 실패 지점입니다.

확인:

```bash
security find-identity -v -p codesigning
```

`ZipBar Dev`가 보이면 됩니다. 이제 다시 빌드하면 이 인증서로 서명됩니다.

```bash
./scripts/build-app.sh
```

## 3. 실행과 권한

```bash
open dist/ZipBar.app
```

**"ZipBar가 이 컴퓨터를 제어하려고 합니다"** 대화상자가 뜹니다.

1. **시스템 설정 열기**
2. 손쉬운 사용 목록에서 **ZipBar 토글 켜기**

권한 없이도 접기/펴기는 되지만, **어느 아이콘이 어느 앱 것인지 알 수 없어**
목록과 넣고 빼기가 동작하지 않습니다. macOS 26이 상태 아이템을 제어 센터에
대신 그리게 하면서, 창 소유자만으로는 앱을 특정할 수 없게 됐기 때문입니다.

### 허용했는데 권한 화면이 그대로라면

실행 중에 부여된 권한은 이미 떠 있는 프로세스에 전달되지 않습니다. 설정
화면의 **[ZipBar 재시작]** 버튼을 누르세요. 그래도 남아 있으면 손쉬운 사용
목록에서 ZipBar를 **뺐다가 다시 추가**하세요 — 옛 서명에 묶인 죽은 항목일 수
있습니다.

```bash
tccutil reset Accessibility com.zipbar.ZipBar
```

이 명령으로 항목을 지우고 앱을 다시 실행하면 새로 요청합니다.

## 4. 쓰는 법

| 동작 | 결과 |
|---|---|
| 슬라임 **클릭** | 넣고 빼는 패널 |
| 슬라임 **⌥클릭** | 접기/펴기 바로 |
| 슬라임 **우클릭** | 메뉴 |

패널에서 아이콘 옆 **[넣기]** / **[꺼내기]**를 누르고 **[적용]**하면 됩니다.

### 재시작은 한 번뿐입니다

**자리를 정할 때만** 그 앱을 한 번 재시작합니다. 아이콘의 자리는 그 앱이
시작할 때 읽히기 때문입니다. 자리가 정해진 뒤로는 감추고 꺼내는 것이 슬라임
클릭만으로 즉시 됩니다.

## 안 되는 것

- **노치 뒤에 가려진 아이콘**은 이 방식으로 꺼낼 수 없습니다.
- **화면 기록 아이콘**처럼 시스템이 우선하는 항목은 숨길 수 없습니다.
- **숨겨진 앱의 알림은 감지할 수 없습니다.** macOS가 다른 앱의 미읽음 상태를
  공개하지 않습니다. 대신 아이콘의 제목이나 크기가 바뀌면 슬라임에 주황 점이
  찍힙니다. Outlook처럼 제목에 상태를 쓰는 앱은 잡히고, 그림만 바뀌는 앱은
  잡히지 않습니다.

## 문제가 생기면

앱에는 진단 모드가 있습니다. 무엇이 실제로 메뉴바에 도달했는지 보여줍니다.

```bash
ZIPBAR_DIAGNOSTIC=1 ./dist/ZipBar.app/Contents/MacOS/ZipBar
```

```
backend=spacer            숨기기 방식
axTrusted=true            접근성 권한
axItems=35                식별한 아이콘 수
buttonImage=31x24         메뉴바에 그려진 글리프 (template=false면 슬라임)
slimeArtwork=5/5          슬라임 그림 로드 상태
```

`axTrusted=false`면 권한 문제입니다. 다만 **셸에서 직접 실행한 진단은 믿을 수
없습니다** — TCC가 접근성 여부를 터미널 앱 기준으로 판정하기 때문에 실제 앱과
다른 답이 나옵니다. 앱이 스스로 기록한 값을 보세요.

```bash
defaults read com.zipbar.ZipBar com.zipbar.beacon.axTrusted
```

## 제거

```bash
pkill -x ZipBar
rm -rf dist/ZipBar.app
defaults delete com.zipbar.ZipBar
tccutil reset Accessibility com.zipbar.ZipBar
```

옮겨둔 아이콘은 각 앱의 설정에 남습니다. 원래대로 되돌리려면 제거 전에 설정에서
전부 **꺼내기** 하고 **적용**하세요.
