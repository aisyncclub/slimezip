사용 흐름

3단계면 끝입니다

처음 한 번만 자리를 정해 두면, 그 뒤로는 클릭만 하면 됩니다.

01

슬라임 클릭

메뉴바의 슬라임을 누르면 지금 있는 아이콘이 전부 나옵니다.

02

넣기 · 꺼내기

감추고 싶은 것 옆의 버튼을 누릅니다. 여러 개를 한 번에 골라도 됩니다.

03

적용

해당 앱을 한 번 재시작하면 자리가 정해집니다. 이후로는 클릭 즉시 감췄다 꺼냈다 합니다.

설치

터미널 세 줄이면 됩니다.

# 1. 빌드 도구 (이미 있으면 건너뛰기)
xcode-select --install

# 2. 내려받아 빌드
git clone https://github.com/aisyncclub/zipbar.git
cd zipbar
./scripts/build-app.sh

# 3. 실행
open dist/ZipBar.app
접근성 권한이 필요합니다. 실행하면 대화상자가 뜹니다. 시스템 설정 → 손쉬운 사용에서 ZipBar를 켜 주세요. 권한 없이는 어느 아이콘이 어느 앱 것인지 알 수 없어 목록이 비어 보입니다.

자주 묻는 질문

먼저 답해 둘 만한 것들입니다.

넣고 뺄 때마다 앱을 재시작해야 하나요?

아니요. 자리를 정할 때만 한 번입니다. 아이콘의 자리는 그 앱이 시작할 때 읽히기 때문입니다. 자리가 정해진 뒤로는 감추고 꺼내는 것이 슬라임 클릭만으로 즉시 됩니다.

왜 접근성 권한이 필요한가요?

macOS 26부터 상태 아이템을 제어 센터가 대신 그립니다. 그래서 창 목록만 보면 모든 아이콘이 "제어 센터 소유"로 보여 주인을 알 수 없습니다. 각 앱이 접근성으로 게시하는 정보를 읽어야 이름을 알 수 있습니다. 권한 없이도 접기·펴기는 됩니다.

노치 뒤에 가려진 아이콘도 꺼낼 수 있나요?

아니요. 이 방식으로는 안 됩니다. 아이콘을 화면 밖으로 밀어 감추는 구조라, 이미 노치에 가려진 것은 되돌릴 수 없습니다.

숨겨 둔 앱의 알림을 알 수 있나요?

알림 자체는 감지할 수 없습니다. macOS가 다른 앱의 미읽음 상태를 공개하지 않습니다. 대신 아이콘의 제목이나 크기가 바뀌면 슬라임에 주황 점이 찍힙니다. Outlook처럼 제목에 상태를 쓰는 앱은 잡히고, 그림만 바뀌는 앱은 잡히지 않습니다.

메뉴바를 차지하지 않나요?

슬라임 하나, 22pt 고정입니다. 몇 개를 물든 넓어지지 않습니다. 개수는 폭이 아니라 눌린 정도로 표시합니다. 메뉴바 자리를 되찾으려는 앱이 그 자리를 먹으면 안 되니까요.

제거하면 아이콘은 원래대로 돌아가나요?

옮겨 둔 자리는 각 앱의 설정에 남습니다. 원래대로 되돌리려면 제거 전에 설정에서 전부 꺼내기 하고 적용하세요.

메뉴바는 슬라임에게 맡기고,
화면은 넓게 쓰세요.

설치는 3분. 자리를 한 번 정해 두면 그 뒤로는 클릭 한 번입니다.
